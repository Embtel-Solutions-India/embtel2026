# Phase 3 — Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The blog is served by the Next.js app from the existing `blogs`/`categories`/`tags` collections — listing, search, category/tag/author pages and post pages with full SEO/AEO/GEO markup, RSS and sitemap entries — with the 6 legacy posts imported and every legacy `/blog` and `/blog/<slug>` URL working.

**Architecture:** TypeScript ports of the legacy Mongoose models on the same collections (additive fields only). Public reads go through `'use cache'` loaders tagged `posts` / `post:<slug>` / `taxonomy`, returning plain objects, exactly like Phase 2 pages. Post HTML is sanitised at render through the Phase 2 sanitiser extended for images. The proxy's published-page index becomes a published-*path* index covering posts, categories, tags and authors, so every unknown blog URL gets a real HTTP 404.

**Tech Stack:** as Phase 2 (Next.js 16.4.2, React 19, Mongoose 8, Zod 3, sanitize-html, cheerio for import, Vitest, Playwright + axe, Lighthouse CI).

**Spec:** `docs/superpowers/specs/2026-10-21-nextjs-migration-design.md` (sections 6.3 Blog/AuthorProfile, 6.4, 6.8). Builds on Phase 2 (`docs/superpowers/plans/2026-10-22-phase-2-public-site.md`).

## Global Constraints

- All Phase 2 Global Constraints still apply (decision A rendering, canonical `https://www.embtelsolutions.com`, dark brand look, plain-text content fields + `*emphasis*`, nonce scripts, no secrets, noindex outside production, no edits to `embtel-final/` or `blog-admin/`, conventional commits with the Co-Authored-By trailer).
- Legacy URLs keep working: `/blog` and `/blog/<slug>` for the 6 existing posts (exact slugs in `embtel-final/includes/blog-posts.js`).
- Collections and fields are shared with the legacy admin until cutover: **only additive schema changes**; never rename or drop a legacy field.
- A post is public only when `status === 'published'`, `publishedAt <= now`, and `isDeleted !== true`. Drafts, scheduled and soft-deleted posts never appear anywhere public (page, list, search, sitemap, RSS, llms.txt, related, author pages).
- Post body HTML is the only rich content; it is sanitised before render (allow-list; images only from internal paths or `https:`).
- No public comments (spec non-goal). No view counter on public reads (it can't coexist with caching; Phase 4 may add analytics-based counts).
- Copy imported verbatim; the "Embtel Team" byline stays.

## Rulings carried into this plan (owner may override)

- **Byline without a user:** imported posts have no author user (legacy byline "Embtel Team" is a name only). `Blog.authorName` (new, optional) stores it; the byline and JSON-LD fall back to the Organization. Author pages exist only for real users with a `slug` and ≥ 1 public post. Phase 4 assigns real authors.
- **Related services (spec 6.4):** `Tag.serviceSlug` (new, optional) links a tag to a service page; posts show up to 3 related service links from their tags. The import seeds the mapping; Phase 4 adds the admin field.
- **Search:** server-side `?q=` on `/blog` using the existing Mongo text index; search result pages are `noindex`. No client-side search JS.
- **RSS** lives at `/feed.xml` (spec 6.2 path). Legacy `?slug=` / `blog-details` URLs are redirected in Phase 6 with the other legacy redirects.

## Review Focus

- A post that is draft, scheduled (future `publishedAt`) or soft-deleted → 404 on its URL and absent from list, search, sitemap, RSS, llms.txt, related posts and author pages (Task 2 test `visibility rules`, Task 10 test `feeds exclude hidden posts`).
- Post HTML with `<script>`, `<iframe>`, `onerror`, `javascript:` links or `http:`/`data:` images → stripped; legitimate `https` images keep `alt` and get `loading="lazy"` (Task 3 test `post html sanitises`).
- Unknown post/category/tag/author slug, and `?page=` beyond the last page or non-numeric → real HTTP 404 (Task 5 and Task 6 tests).
- Search text containing regex/operator characters (`.*`, `$where`, quotes) or 1 000 characters → no crash, safe text search, page `noindex` (Task 2 test `search input is inert`, Task 6 e2e).
- A post with no author user, no featured image or no category → renders without broken images; JSON-LD author is the Organization (Task 7 and Task 9 tests).

  - Image fields validated: `featuredImage` kept only if internal path or `https:` (else `null`).
